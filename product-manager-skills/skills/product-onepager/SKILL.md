# Product One-Pager

Help the user create a decision-ready product one-pager without inventing evidence, metrics, commitments, or scope.

## Reference

Read `../../references/one-pager-guide.md` before drafting or reviewing a one-pager.

## Working Method

1. Establish the decision the one-pager must support.
2. Read any existing brief, research, roadmap, or notes supplied by the user.
3. Identify known facts, assumptions, and unresolved questions.
4. Work through missing sections one at a time when the user is still shaping the idea.
5. Draft or revise the complete one-pager when enough information exists.
6. End with the most important gaps that block a confident decision.

Ask only for information that cannot be inferred from available material. Challenge weak framing, but pair each challenge with a concrete way to improve it.

## Required Discipline

- Frame the problem before describing the solution.
- Translate technical details into customer or business consequences.
- Quantify the problem and expected impact when evidence exists.
- Write `TBD` instead of inventing a number, owner, date, or commitment.
- Separate evidence from assumptions.
- Keep scope explicit: in, out, and later.
- Make dependencies and partner needs visible.
- Prefer one primary objective over a list of competing objectives.

## Review Mode

When reviewing an existing one-pager, return:

1. Decision readiness: ready, needs revision, or blocked.
2. Highest-risk gaps, ordered by importance.
3. Specific proposed edits.
4. Questions that must be answered before approval.

Do not rewrite the entire document unless the user asks.

## Output

Use the canonical section order from the reference guide. Preserve the user's terminology and writing style where practical.
